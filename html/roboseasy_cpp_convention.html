클래스 / 구조체

NAMING
PascalCase (대문자로 시작, 단어마다 대문자)

모든 클래스와 구조체는 PascalCase를 따른다. 약어도 첫 글자만 대문자로 처리하는 것이 원칙이나, 로봇명 등 고유명사는 전체 대문자 허용.

✓ GOOD
class StateEstimator : public rclcpp::Node {};
class RobosEasyJointController {};
struct JointID {};
class ALICE4State {};   // 로봇 고유명사
class JointFilter {};
✗ BAD
class state_estimator {};   // snake_case X
class stateEstimator {};    // camelCase X
class STATEESTIMATOR {};   // 전체 대문자 X
struct joint_id {};          // snake_case X
2

함수 / 메서드

NAMING
PascalCase — 동사로 시작하는 것을 권장

모든 멤버 함수와 자유 함수는 PascalCase를 사용한다. 동작을 명확히 표현하는 동사(Get, Set, Update, Calculate, Handle, Is, Has 등)로 시작하는 것이 권장된다.

✓ GOOD
void TimerCallback();
void UpdateStateFromInterfaces();
bool ReadStateFromCommandInterfaces();
EndpointState GetEndpointPose(const std::string &name);
void HandleShutdownSignal(int signum);
void ImuCallback(const Imu::SharedPtr msg);
double GetTotalMass();
✗ BAD
void timer_callback();      // snake_case X
void timerCallback();       // camelCase X
void update();               // 동작 불명확
void cb();                    // 약어 X
접두사 패턴: Get/Set (접근자), Is/Has (bool 반환), Update/Refresh (갱신), Calculate/Compute (계산), Handle (이벤트 처리), Load/Save (입출력), Publish/Subscribe (ROS2)
3

멤버 변수

NAMING
snake_case + 후행 밑줄 (_)

클래스 멤버 변수는 모두 소문자 snake_case로 작성하고, 이름 끝에 밑줄 _을 붙여 로컬 변수와 구분한다. 스마트 포인터, atomic 변수, 필터 객체 모두 동일 규칙을 따른다.

✓ GOOD
private:
  int odometry_mode_;
  double control_time_;
  std::atomic<bool> imu_tare_request_;
  bool is_l_foot_contact_;
  std::unique_ptr<LowPassFilter> com_x_lpf_;
  rclcpp::TimerBase::SharedPtr control_timer_;
✗ BAD
private:
  int odometryMode;      // camelCase X
  double ControlTime;    // PascalCase X
  bool m_isContact;      // m_ 헝가리안 X
  bool isContact;        // 후행 _ 누락 X
중요: 로컬 변수와 멤버 변수를 구분하는 핵심 규칙이다. 후행 _가 없으면 멤버 변수임을 인식하기 어려워진다.

로컬 변수 / 함수 파라미터

NAMING
snake_case (후행 밑줄 없음)

함수 내부의 로컬 변수와 함수 파라미터는 snake_case를 사용하되 후행 _ 없이 쓴다. 멤버 변수와 명확히 구분된다.

✓ GOOD
void ImuCallback(
  const Imu::SharedPtr msg)   // 파라미터
{
  double time_tolerance = 0.1;   // 로컬 변수
  Imu::SharedPtr imu_msg = nullptr;
  std::string urdf_path;
  rclcpp::Time latest_time = now();
}
✗ BAD
void ImuCallback( const Imu::SharedPtr Msg) // 대문자 X { double timeTolerance = 0.1; // camelCase X double time_tolerance_; // 후행 _ X std::string p; // 의미 없는 단문자 X }
4+

Boolean 변수 네이밍

NAMING
반드시 is_ 또는 has_ 접두사로 시작

bool 타입의 변수는 반드시 is_ 또는 has_ 접두사로 시작한다. 이 규칙 덕분에 변수명을 보는 순간 타입 선언 없이도 true/false 값을 가진다는 것을 즉시 알 수 있다. 네이밍만으로 타입을 전달하는 가장 기본적인 가독성 규칙이다.

접두사 선택 기준
is_
상태/조건을 묻는 경우
"~인가? / ~한가?"
has_
인터페이스/기능 보유 여부
"~를 가지고 있는가?"
✓ GOOD — is_ (상태/조건)
// 멤버 변수 (후행 _ 포함)
bool is_l_foot_contact_;
bool is_r_foot_contact_;
bool is_active_;
bool is_initialized_;

// 로컬 변수 (후행 _ 없음)
bool is_valid = true;
bool is_empty = queue.empty();
bool is_linear_mode = true;
✓ GOOD — has_ (인터페이스 보유)
// 멤버 변수
bool has_velocity_state_interface_;
bool has_acceleration_state_interface_;
bool has_effort_command_interface_;

// 로컬 변수
bool has_values = true;
bool has_linear_actuator = false;
bool has_valid_data = !queue.empty();
✗ BAD — 접두사 없음
bool left_foot_contact;  // is_ 누락
bool velocity_interface;  // has_ 누락
bool linear;              // 타입 불분명
bool active;              // 타입 불분명
bool flag;                // 의미 없음
✗ BAD — 잘못된 접두사
bool bIsContact;         // 헝가리안 b X
bool IsContact;           // PascalCase X
bool check_contact;       // 동사 시작 X
bool contact_status;      // _status 접미사 X
한 눈에 알아보는 예시:   if (is_l_foot_contact_ && has_velocity_state_interface_)  — 변수명만 봐도 둘 다 bool임을 즉시 인식할 수 있다.
5

열거형 (Enum)

NAMING
타입명은 PascalCase, 값은 enum에 따라 다름

enum 타입명은 PascalCase. enum class 값은 PascalCase, 일반 enum 값은 UPPER_SNAKE_CASE를 사용한다. 타입 안전성을 위해 enum class 사용을 권장한다.

✓ GOOD — enum class (권장)
enum class FilterType
{
  Pos,       // 위치 필터
  Vel,       // 속도 필터
  Torque,   // 토크 필터
  Count
};

// 사용
FilterType t = FilterType::Vel;
✓ GOOD — 일반 enum
enum Filter { NO_FILTERING = 0, LOW_PASS_FILTER = 1, ONE_EURO_FILTER = 2, }; // 사용 Filter f = LOW_PASS_FILTER;
6

상수 / constexpr

NAMING
static constexpr 멤버: snake_case / 자유 상수: kCamelCase 또는 UPPER_SNAKE

구조체 내부 static constexpr 멤버는 snake_case (물리적 의미를 담은 이름 사용). 전역 constexpr 및 const는 UPPER_SNAKE_CASE 사용.

✓ GOOD
struct JointID
{
  static constexpr uint8_t fixed_base   = 0;
  static constexpr uint8_t l_hip_y      = 11;
  static constexpr uint8_t r_knee_p     = 20;
  static constexpr uint8_t joint_count  = 40;
};

constexpr double GRAVITY_ACCEL = 9.80665;
7

매크로 / 전처리기 (#define)

NAMING
UPPER_SNAKE_CASE — 조건부 컴파일 플래그에만 사용

매크로는 모두 대문자 UPPER_SNAKE_CASE로 정의한다. 주로 로봇 버전 분기나 플랫폼 조건부 컴파일에 사용. 단순 상수에는 사용하지 않고 constexpr로 대체할 것.

✓ GOOD
#define ALICE         1
#define ALICE_VERSION 2

#if ALICE
  // Alice 로봇 전용 코드
#endif
✗ BAD
#define gravity 9.80665  // 소문자 X
#define Alice   1         // PascalCase X
#define MAX_JOINTS 40     // constexpr로 대체

네임스페이스

NAMING
lowercase_snake_case — 패키지명과 동일하게

네임스페이스는 ROS2 패키지명과 일치시켜 전부 소문자 snake_case로 작성한다. 중첩 네임스페이스는 패키지 계층을 반영한다.

✓ GOOD
namespace aeirobot
{
  class StateEstimator {};
} // namespace roboseasy

namespace roboseasy_joint_controller
{
  class RobosEasyJointController {};
} // namespace roboseasy_joint_controller
닫는 괄호에 반드시 // namespace 이름 주석을 붙인다.

타입 별칭 (using)

NAMING
PascalCase — ROS2 메시지 타입 단축명에 주로 사용

긴 ROS2 메시지 타입은 using으로 별칭을 선언해 코드 가독성을 높인다. 별칭은 PascalCase로 작성한다.

✓ GOOD
using Imu         = sensor_msgs::msg::Imu;
using JointState  = sensor_msgs::msg::JointState;
using RobotState  = roboseasy_state_msgs::msg::RobotState;
using FsrState    = roboseasy_state_msgs::msg::FsrState;
using RobotPose   = alice_walking_module_msgs::msg::RobotPose;

파일명

STYLE
lowercase_snake_case + 확장자 (.hpp / .cpp)

헤더 파일은 .hpp, 구현 파일은 .cpp 확장자를 사용한다. 파일명은 전부 소문자 snake_case.

✓ GOOD
roboseasy_state_estimator.hpp
roboseasy_state_estimator.cpp
roboseasy_joint_controller.hpp
alice4_state_estimator.hpp
✗ BAD
StateEstimator.hpp      // PascalCase X
stateEstimator.h        // .h 확장자 X
RobosEasyController.HPP  // 대문자 확장자 X
11

헤더 가드

STRUCT
#ifndef 방식 — PACKAGE_FILENAME_HPP_ 형식

헤더 가드는 #ifndef / #define / #endif 방식 사용. 형식은 전체 대문자 + 경로_파일명_HPP_ (후행 밑줄 포함).

✓ GOOD
// 파일: roboseasy_state_estimator.hpp
#ifndef ROBOSEASY_STATE_ESTIMATOR_HPP_
#define ROBOSEASY_STATE_ESTIMATOR_HPP_

// ... 헤더 내용 ...

#endif // ROBOSEASY_STATE_ESTIMATOR_HPP_

// 파일: alice4_state.hpp
#ifndef ALICE4STATE_HPP
#define ALICE4STATE_HPP
#pragma once도 허용되나, 팀 내 통일 필요. 현 코드베이스는 #ifndef 방식을 표준으로 사용.

인클루드 순서

STRUCT
표준 라이브러리 → ROS2 → 외부 라이브러리 → 자체 헤더

인클루드는 의존성 범위를 기준으로 4단계로 그룹화하고, 각 그룹 사이에 빈 줄을 둔다.

✓ GOOD
// 1) 표준 라이브러리 (C++ STL)
#include <atomic>
#include <string>
#include <vector>
#include <memory>
#include <mutex>

// 2) ROS2 메시지 / 코어
#include <rclcpp/rclcpp.hpp>
#include <sensor_msgs/msg/imu.hpp>
#include <nav_msgs/msg/odometry.hpp>

// 3) 외부 라이브러리 (Eigen, Pinocchio 등)
#include <Eigen/Dense>
#include <pinocchio/parsers/urdf.hpp>

// 4) 자체(패키지 내) 헤더
#include "roboseasy_toolbox/basic_tools.hpp"
#include "roboseasy_math/math_tool.hpp"
13

스마트 포인터

STYLE
unique_ptr 기본 / shared_ptr는 공유 소유권이 필요한 경우만

Raw 포인터 사용을 금지하고 스마트 포인터를 사용한다. 단독 소유는 std::unique_ptr, 공유 소유는 std::shared_ptr. ROS2 내장 타입은 SharedPtr 관용어를 따른다.

✓ GOOD
// 단독 소유 — unique_ptr
std::unique_ptr<ALICE4State>    alice4_state_;
std::unique_ptr<LowPassFilter>  com_x_lpf_;
std::unique_ptr<OneEuroFilter>  dcm_x_oef_;

// 생성 — make_unique 사용
alice4_state_ = std::make_unique<ALICE4State>();
com_x_lpf_ = std::make_unique<LowPassFilter>(clock, cutoff);

// ROS2 공유 포인터
rclcpp::Publisher<RobotState>::SharedPtr state_publisher_;
rclcpp::Subscription<Imu>::SharedPtr     imu_subscriber_;

조건부 컴파일

STRUCT
#if / #endif — 로봇 버전 분기에 사용, 반드시 주석 명시

로봇 종류나 버전별 코드 분기는 #if로 처리한다. #endif에 반드시 해당 조건 주석을 달고, 사용 플래그는 파일 상단에 정의한다.

✓ GOOD
#define ALICE 1  // 파일 상단 또는 CMake에서 정의

#if ALICE
  std::unique_ptr<ALICE4State> alice4_state_;
  void UpdateJointsFromJointState(ALICE4State &state,
                                   const JointState &js);
#endif // ALICE

// 구현부에서도 동일하게
#if ALICE
  alice4_state_ = std::make_unique<ALICE4State>();
#endif // ALICE

Doxygen 주석

DOCS
헤더 파일에서 /** */ 블록 주석 — @brief, @param, @return 필수

헤더 파일의 모든 public 클래스, 구조체, 함수에 Doxygen 주석을 작성한다. @brief는 한 줄 요약, @param은 파라미터 설명, @return은 반환값을 기술한다.

✓ GOOD
/**
 * @file roboseasy_state_estimator.hpp
 * @brief 로봇 상태 추정기 클래스 정의
 */

/**
 * @class StateEstimator
 * @brief 각종 센서 데이터를 받아 상태를 추정하는 클래스
 */
class StateEstimator : public rclcpp::Node
{
public:
  /**
   * @brief 생성자
   * @param node_name ROS2 노드명 (기본값: "roboseasy_state_estimator")
   */
  explicit StateEstimator(const std::string &node_name
                          = "roboseasy_state_estimator");

  /**
   * @brief ZMP 계산
   * @return 반환값 없음
   */
  void CalculateZMP();

  /**
   * @brief 전체 질량 계산
   * @return 로봇 전체 질량 (kg)
   */
  double GetTotalMass();
};

인라인 주석

DOCS
구현부 한글 주석 허용 — 알고리즘/좌표계/물리 의미 설명에 활용

구현 파일(.cpp) 내 인라인 주석은 한국어를 허용한다. 특히 좌표 변환, 물리 공식, 역기구학 계산 등 수식의 의미를 명확히 설명할 때 적극 활용한다. 임시 코드에는 // 일단주석 등 추후 정리 예정임을 명시한다.

✓ GOOD
// (1) pitch *= -1 처리
pitch *= -1.0;

// (2) 점 B를 "한 번에" 계산
// p_b_x = (-r + 0.064)*sin(pitch) - 0.05*cos(pitch)
const double p_b_x = (-r + 0.064) * std::sin(pitch)
                      - 0.05 * std::cos(pitch);

// (3) BC = BO + OC (벡터 합산)
const double bc_x = bo_x + oc_x;

// 일단주석 — 추후 position interface 활성화 시 해제
// CheckAndAssign(has_position_command_interface, ...);

DOCS
대형 구현 파일에서 기능 그룹을 ASCII 배너로 구분

✓ GOOD
/*********************************************************

   |  ___(_) | |_ ___ _ __
   | |_  | | | __/ _ \ '__|
   |  _| | | | ||  __/ |
   |_|   |_|_|\__\___|_|

  *********************************************************/

/*********************************************************
 __     ___                 _
 \ \   / (_)___ _   _  __ _| |
  \ \ / /| / __| | | |/ _` | |
   \ V / | \__ \ |_| | (_| | |

  *********************************************************/
권장 사용 시점: 클래스 하나의 구현이 여러 .cpp로 분할되거나 한 파일 내에서 초기화 / 콜백 / 계산 / 퍼블리시 섹션이 뚜렷이 구분될 때.

경로 처리 (이식성) ⭐

PORTABILITY
절대 경로 하드코딩 금지 — 패키지 리소스 / 파라미터 기준으로 작성

개발자 개인 PC 계정에 종속된 절대 경로(/home/철수/...)를 코드에 박아두면 남이 클론했을 때 곧바로 깨진다. URDF·설정·리소스 위치는 항상 ROS2 패키지 share 디렉터리(ament_index_cpp)나 파라미터·환경 변수로 조회해, 누구나 그대로 빌드·실행할 수 있게 한다. 경로 결합은 std::filesystem으로 처리한다.

✓ GOOD
#include <filesystem>
#include <ament_index_cpp/get_package_share_directory.hpp>

namespace fs = std::filesystem;

// 패키지 share 디렉터리 기준 (누구나 실행 가능)
const fs::path pkg_share =
  ament_index_cpp::get_package_share_directory("roboseasy_bringup");
const fs::path urdf_path = pkg_share / "urdf" / "roboseasy.urdf";

// 경로를 ROS2 파라미터로 주입 (launch에서 지정)
this->declare_parameter<std::string>("urdf_path", "");
const std::string p =
  this->get_parameter("urdf_path").as_string();
✗ BAD
// 개인 계정 / 특정 PC 절대 경로 하드코딩
const std::string urdf_path =
  "/home/chulsoo/ws/urdf/roboseasy.urdf";
// ↑ 계정명 종속 X — 남이 클론하면 깨짐

const std::string config =
  "/home/chulsoo/config/robot.yaml";
// ↑ 절대 경로 하드코딩 X

std::ifstream f("C:/Users/roboseasy/data.csv");
// ↑ 특정 PC 종속 X
핵심: 경로는 "내 PC에서만 되는 코드"의 대표적 원인이다. C++/ROS2에서는 ament_index_cpp::get_package_share_directory() 또는 launch 파일이 넘겨주는 파라미터를 기본으로 삼고, 문자열로 시작하는 절대 경로가 코드에 보이면 리뷰에서 반드시 지적한다. 경로 결합·정규화는 std::filesystem::path로 처리한다.
